# Profile

## Perfil: el usuario puede cambiar su correo, confirmando la contraseña actual
Desde 2026-10-13 (pedido del usuario; antes el correo NO era editable desde el perfil) Profile/Edit.vue permite editar `email`. ProfileUpdateRequest: email `sometimes|required|email|max:255|unique(users) ignore propio` (trim en prepareForValidation; omitirlo = no cambia) y `current_password` = Rule::requiredIf(cambiaElCorreo()) + `current_password:web` — el correo es la credencial de login (web y app), así que una sesión abierta no basta para tomar la cuenta. cambiaElCorreo() compara sin mayúsculas (sólo cambiar mayúsculas no pide contraseña). ProfileController::update() evalúa cambiaElCorreo() ANTES de guardar (después el user ya tiene el correo nuevo) y hace unset de current_password (nunca se persiste). No se toca email_verified_at: User no implementa MustVerifyEmail, el middleware 'verified' del dashboard no bloquea. Front: el campo "Contraseña actual" sólo aparece si correoCambiado; form.transform manda current_password vacío si no cambió. La API (PUT/PATCH /api/v1/auth/me, Api\V1\AuthController::updateMe) aplica la MISMA regla desde openapi 1.15.0: email sometimes|required|email|unique ignore propio + current_password requiredIf + `current_password:api`, trim manual de email, cambiaElCorreo calculado antes de guardar. La lógica "¿cambia el correo?" vive en User::cambiaraElCorreoA() (la usan web y API). El JWT sigue válido tras el cambio (sub = id). Reenviar el mismo correo no pide contraseña (compatibilidad con la app instalada); email vacío/null → 422. Tests: tests/Feature/Api/V1/AuthControllerTest.php. Tests: tests/Feature/ProfileTest.php.
